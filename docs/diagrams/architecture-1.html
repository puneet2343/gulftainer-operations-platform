Production architecture on AWS (1 of 2): clients, edge and application

Static front end on CloudFront, HTTP APIs on Lambda behind API Gateway, identity federated from Gulftainer's Microsoft Entra ID through Cognito.

Clients

Operations web appNext.js 16 and React 19. Terminal, logistics, finance and control modules.
Customer e-servicesVessel schedule, container enquiry, e-token portal, online payment.
Gate and yard devicesProgressive web app on Intune-managed tablets with an offline queue.
External systemsShipping-line EDI, Sharjah Customs, carrier tracking, SAP S/4HANA.
HTTPS, TLS 1.2 or laterWAF rules and rate limits

Edge and identity

Amazon CloudFrontStatic assets and pages, caching, origin shield, UAE edge locations.
AWS WAF and ShieldOWASP managed rules, bot control, geographic rules, DDoS protection.
Amazon CognitoOIDC federation to Entra ID: single sign-on, MFA and Conditional Access enforced by Gulftainer IT.
Amazon API GatewayHTTP API with JWT authoriser, per-client throttling, usage plans for partners.
Signed requests with idempotency keys

Application: AWS Lambda, Node.js 22, TypeScript

Terminal serviceVessel calls, containers, holds, customs, delivery orders, yard moves.
Gate serviceE-tokens, marshalling yard, gate-in and gate-out, EIR.
Logistics serviceInland transfers, transport jobs, proof of delivery.
Warehouse serviceOrders, stock ledger, approvals, reversals.
Finance serviceTariff, charges, invoices, payments, SAP postings.
Integration workersEDI parsing, customs and carrier events, de-duplication.
Scheduled jobsToken expiry, uncollected sweep, overdue invoices, reefer alerts.
Shared layerAuthorisation context, audit, outbox publisher, tracing.
Each service is a group of Lambda functions behind its own routes. The business rules are the same TypeScript modules as the prototype's service layer, so validated behaviour carries over unchanged.
