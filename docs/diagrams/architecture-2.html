Production architecture on AWS (2 of 2): data, messaging and operations

PostgreSQL is the system of record; DynamoDB serves high-rate operational keys; S3 holds documents; MongoDB holds histories and feeds. Events leave the database through a transactional outbox.

Data and messaging

Amazon Aurora PostgreSQLSystem of record: containers, vessel calls, stock ledger, invoices, audit. Multi-AZ, point-in-time recovery, read replica for reporting.
Amazon DynamoDBE-token slot counters, gate device sessions, idempotency keys, offline queue acknowledgements, throttle counters.
Amazon S3Delivery orders, EIRs, DG declarations, proofs of delivery. SSE-KMS encryption, versioning, Object Lock for legal records.
MongoDB Atlas on AWS (me-central-1)Container event history, notification feed, integration message archive, reefer time series, report snapshots.
Amazon EventBridge and SQSDomain events from the outbox, retries with exponential backoff, dead-letter queues for reconciliation.
Amazon ElastiCache for RedisVessel schedule and tariff cache, portal session throttles.
Amazon SES and SNSEmail and SMS to consignees and hauliers: container ready, token confirmation, invoice issued.

Operations, security and continuity

ObservabilityCloudWatch metrics and logs, X-Ray tracing, OpenTelemetry export to Grafana; Zabbix for on-site gate hardware.
Secrets and keysSecrets Manager, KMS customer-managed keys, IAM least privilege, no long-lived credentials.
ResilienceMulti-AZ everywhere, automated backups, cross-region read replica, quarterly restore drills. RTO 60 minutes, RPO 5 minutes.
DeliveryGitHub Actions, AWS CDK infrastructure as code, development, test, staging and production accounts, canary releases with automatic rollback.
ComplianceISO 27001 control mapping, immutable audit log, data residency in the UAE region, retention and deletion policies per document type.
