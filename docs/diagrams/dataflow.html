Where each kind of data lives

Polyglot persistence by access pattern: the relational system of record keeps transactional truth, DynamoDB serves high-rate keys, S3 holds files, MongoDB holds append-only histories and feeds that are read far more often than written.

Aurora PostgreSQL

Transactional system of record, strict constraints, row-level locking

  • Organisations, locations, users and roles
  • Parties, vessel calls, containers, holds, delivery orders
  • Stock ledger (append-only) and derived balances
  • Warehouse orders, transport jobs, inland transfers
  • Tariff, charges, invoices, payments
  • Audit log, hash-chained
  • Transactional outbox

DynamoDB

Millisecond keys at terminal gate rates, TTL for expiry

  • Idempotency keys: request id to result, 24-hour TTL
  • E-token slot capacity per terminal and hour
  • Gate device sessions and offline acknowledgements
  • Rate-limit and throttle counters
  • Live yard position index
  • Vessel schedule snapshot for the public site

Amazon S3

Encrypted, versioned objects; Object Lock for legal documents

  • Delivery orders, bills of lading, customs declarations
  • Equipment interchange receipts and gate photographs
  • DG declarations, VGM certificates, inspection reports
  • Proofs of delivery
  • EDI archive: BAPLIE, COPRAR, CODECO
  • Report exports and nightly extracts

MongoDB Atlas

Flexible documents for histories and feeds, time-series collections

  • Container event history, one document per container
  • Notification feed per role and user
  • Integration message log with de-duplication index
  • Reefer temperature readings
  • Report snapshots and dashboard aggregates
  • Portal activity and search material

A gate-out request, end to end

1. Gate tabletPOST /gate/out with idempotency key, token id, seal check and EIR remarks
→
2. API Gateway and CognitoJWT validated; role gate officer; location scope checked
→
3. Lambda gate serviceDynamoDB conditional put on the key; a repeat returns the stored result
→
4. PostgreSQL transactionRe-check release conditions; write gate transaction, container state, storage top-up, audit, outbox
→
5. Outbox publisherEventBridge event; SQS consumers update MongoDB history, notify the consignee, post to SAP
Failure isolationIf step 4 fails nothing is written and the device shows the rule that blocked release. If step 5 fails the business transaction stands; the event retries with backoff and lands in a dead-letter queue for reconciliation.
